# F5 复盘与动态调整测试用例文档

## 1. 测试目标

F5 的目标是：用户在 F3 标记任务进度后，系统可以统计完成情况，识别延期和连续未完成任务，生成复盘报告，并基于剩余时间重排后续计划。调整后的计划必须先预览，只有用户确认后才保存并回到 F3 展示。

本测试文档覆盖：

- 任务完成率统计
- 延期任务识别
- 连续未完成任务识别
- 本周复盘报告生成
- 薄弱知识点分析
- 强化任务生成
- 后续计划重排
- 重排结果约束校验
- 用户确认前不覆盖原计划
- 用户确认后保存新计划
- Streamlit 页面交互要求
- FakeLLM 与 RealLLM 可切换测试边界

## 2. 功能边界

### 2.1 输入

F5 至少接收：

- 当前 `StudyPlan`
- 当前日期
- 任务完成状态
- 用户复盘文本
- 延期任务
- 薄弱点
- 可选：资料问答或知识点提取结果

### 2.2 输出

F5 至少输出：

- `ReviewReport`
- 完成率分析
- 延期任务处理建议
- 连续未完成任务分析
- 薄弱知识点强化任务
- `AdjustedStudyPlan`
- 调整前后差异
- 下一阶段学习建议

### 2.3 不做范围

MVP 阶段不要求：

- 多用户复盘
- 自动日历同步
- 自动提醒
- 长期学习习惯画像
- 复杂强化学习式推荐

## 3. 建议领域模型

测试用例可以驱动后续实现以下模型：

```python
TaskProgress
ReviewReport
ReplanRequest
AdjustedStudyPlan
PlanAdjustmentPreview
```

字段建议：

```text
TaskProgress
  - task_id
  - status
  - planned_date
  - actual_completed_at
  - duration_minutes
  - related_topics
  - notes

ReviewReport
  - period_start
  - period_end
  - completion_rate
  - completed_task_count
  - total_task_count
  - overdue_tasks
  - consecutive_unfinished_topics
  - weak_points
  - summary
  - suggestions

ReplanRequest
  - original_plan
  - review_report
  - remaining_tasks
  - remaining_days
  - daily_available_minutes

AdjustedStudyPlan
  - original_plan
  - adjusted_plan
  - review_report
  - changed_tasks
  - warnings
  - saved
```

## 4. 阶段一：进度统计与复盘输入

### TC-F5-001 空计划不能生成复盘

前置条件：

- 当前没有 `StudyPlan`

操作：

- 调用复盘入口或打开复盘页面

期望结果：

- 返回明确提示：需要先生成学习计划
- 不调用 LLM
- 不生成 `ReviewReport`

编写原因：

- F5 依赖 F3 的计划和任务状态，空计划时必须有保护。

### TC-F5-002 完成率统计正确

前置条件：

- 计划中有 10 个任务
- 其中 6 个 `done`
- 2 个 `todo`
- 1 个 `doing`
- 1 个 `skipped`

操作：

- 统计当前周期完成率

期望结果：

- `total_task_count == 10`
- `completed_task_count == 6`
- `completion_rate == 0.6`
- `skipped` 不计入完成任务

编写原因：

- 完成率是复盘报告和是否重排的基础指标。

### TC-F5-003 只统计当前复盘周期内任务

前置条件：

- 计划包含上周、本周、下周任务
- 当前复盘周期为本周

操作：

- 统计本周完成情况

期望结果：

- 只统计本周任务
- 上周和下周任务不影响本周完成率

编写原因：

- F5 的“本周复盘”必须按周期计算，不能被全计划任务污染。

### TC-F5-004 用户复盘文本可以为空

前置条件：

- 有有效计划和任务状态
- 用户没有填写复盘文本

操作：

- 生成复盘报告

期望结果：

- 系统仍可基于任务状态生成报告
- `user_review_text` 为空不报错

编写原因：

- 复盘输入框是增强信息，不应阻塞自动复盘。

### TC-F5-005 用户复盘文本会进入报告上下文

前置条件：

- 用户填写：“这周递归部分理解不好，练习时间不够。”

操作：

- 生成复盘报告

期望结果：

- 报告中包含或反映“递归”“练习时间不够”
- 薄弱点中包含递归相关内容

编写原因：

- 用户主观反馈是动态调整的重要输入。

## 5. 阶段二：延期与风险识别

### TC-F5-006 识别延期任务

前置条件：

- 当前日期为 2026-06-03
- 任务 A 日期为 2026-06-01，状态 `todo`
- 任务 B 日期为 2026-06-02，状态 `doing`
- 任务 C 日期为 2026-06-03，状态 `todo`

操作：

- 分析延期任务

期望结果：

- 任务 A 和任务 B 被识别为延期
- 任务 C 不被识别为延期

编写原因：

- 延期判断必须基于任务日期和当前日期。

### TC-F5-007 已完成的过去任务不算延期

前置条件：

- 当前日期为 2026-06-03
- 任务日期为 2026-06-01
- 状态为 `done`

操作：

- 分析延期任务

期望结果：

- 该任务不在延期列表中

编写原因：

- 已完成任务不应触发重排压力。

### TC-F5-008 skipped 任务进入风险分析

前置条件：

- 某任务状态为 `skipped`
- 任务日期早于当前日期

操作：

- 分析复盘风险

期望结果：

- 该任务进入未完成或跳过任务分析
- 报告给出补救建议

编写原因：

- 跳过任务不是完成，可能代表时间不足或难度过高。

### TC-F5-009 识别连续未完成知识点

前置条件：

- 连续 3 个任务都关联知识点 `动态规划`
- 状态均为 `todo` 或 `skipped`

操作：

- 分析连续未完成主题

期望结果：

- `动态规划` 被识别为连续未完成知识点
- 报告建议降低任务粒度或安排强化练习

编写原因：

- 连续失败比单个延期更能说明学习阻塞。

### TC-F5-010 单次未完成不算连续风险

前置条件：

- 只有 1 个 `递归` 任务未完成
- 其他递归任务已完成

操作：

- 分析连续未完成主题

期望结果：

- `递归` 不进入连续未完成知识点列表

编写原因：

- 避免过度诊断，减少错误重排。

## 6. 阶段三：复盘报告生成

### TC-F5-011 FakeLLM 可生成结构化复盘报告

前置条件：

- `USE_REAL_LLM=false`
- FakeLLM 返回合法复盘 payload

操作：

- 调用 `GenerateReviewReportUseCase`

期望结果：

- 返回 `ReviewReport`
- 包含完成率、延期任务、薄弱点、建议

编写原因：

- 自动化测试默认不依赖真实 LLM。

### TC-F5-012 真实 LLM 开关生效

前置条件：

- `.env` 中 `USE_REAL_LLM=true`
- DeepSeek 配置完整

操作：

- 构建 F5 LLM 服务

期望结果：

- 使用真实 DeepSeek 适配器
- 不使用 FakeLLM

编写原因：

- 所有涉及 LLM 的功能都必须服从统一 `USE_REAL_LLM` 开关。

### TC-F5-013 复盘报告字段完整

前置条件：

- 有任务进度和用户复盘文本

操作：

- 生成复盘报告

期望结果：

- `summary` 非空
- `completion_rate` 有值
- `overdue_tasks` 是列表
- `weak_points` 是列表
- `suggestions` 非空

编写原因：

- F5 页面和重排逻辑依赖这些字段。

### TC-F5-014 LLM 返回非 JSON 时失败可控

前置条件：

- FakeLLM 返回普通自然语言，非 JSON

操作：

- 生成复盘报告

期望结果：

- 抛出可理解的应用层错误
- 不生成半成品报告

编写原因：

- 防止 LLM 输出格式不稳定导致页面崩溃。

### TC-F5-015 LLM 返回缺字段时校验失败

前置条件：

- FakeLLM 返回缺少 `suggestions` 或 `completion_rate` 的 JSON

操作：

- 解析复盘报告

期望结果：

- 校验失败
- 错误信息指出缺失字段

编写原因：

- 结构化输出必须严格校验。

## 7. 阶段四：重排请求构造

### TC-F5-016 全部完成时不需要大幅重排

前置条件：

- 当前周期所有任务都是 `done`

操作：

- 构造 `ReplanRequest`

期望结果：

- `need_replan == False` 或重排类型为 `minor`
- 不移动后续大部分任务
- 只生成下一阶段建议

编写原因：

- 全部完成时应鼓励继续执行，而不是制造不必要变化。

### TC-F5-017 有延期任务时需要重排

前置条件：

- 存在多个延期任务

操作：

- 构造 `ReplanRequest`

期望结果：

- `need_replan == True`
- 延期任务进入 `remaining_tasks`
- 重排上下文包含剩余天数和每日可用时间

编写原因：

- 延期任务是动态调整的核心触发条件。

### TC-F5-018 只重排未完成任务

前置条件：

- 计划中有已完成任务和未完成任务

操作：

- 构造重排请求

期望结果：

- `done` 任务不进入待重排任务
- `todo`、`doing`、`skipped` 可进入待重排任务

编写原因：

- 已完成任务不应被重新安排。

### TC-F5-019 重排请求保留原计划引用

前置条件：

- 当前有完整 `StudyPlan`

操作：

- 构造 `ReplanRequest`

期望结果：

- 请求中保留 `original_plan`
- 后续可生成调整前后对比

编写原因：

- 页面需要展示调整前后差异，保存前也要防止覆盖。

## 8. 阶段五：计划重排与约束校验

### TC-F5-020 重排后任务日期不早于今天

前置条件：

- 当前日期为 2026-06-03
- 存在延期任务

操作：

- 生成调整后计划

期望结果：

- 所有未完成任务的新日期都不早于 2026-06-03

编写原因：

- 新计划不能继续安排在过去。

### TC-F5-021 重排后任务不超过截止日期

前置条件：

- 学习目标截止日期为 2026-06-30

操作：

- 生成调整后计划

期望结果：

- 所有任务日期都不晚于 2026-06-30

编写原因：

- F5 必须遵守用户目标约束。

### TC-F5-022 重排后每日总时长不超限

前置条件：

- 用户每日可学习 120 分钟
- 有多个待重排任务

操作：

- 生成调整后计划

期望结果：

- 任意一天任务总时长都不超过 120 分钟

编写原因：

- 防止动态调整生成不可执行计划。

### TC-F5-023 时间不足时返回风险提示

前置条件：

- 剩余任务总时长明显超过剩余可用时间

操作：

- 生成调整后计划

期望结果：

- 系统不静默生成超载计划
- 返回风险提示，例如需要降低目标、增加学习时间或延后截止日期

编写原因：

- 当约束不可满足时，应暴露冲突，而不是伪造可行计划。

### TC-F5-024 重排保留阶段/周/日三级结构

前置条件：

- 原计划包含 phases、weekly_plans、tasks

操作：

- 生成调整后计划

期望结果：

- 调整后计划仍包含阶段、周、日三级结构
- 不丢失原有阶段目标和复习安排

编写原因：

- F5 输出必须能回到 F3 展示。

### TC-F5-025 强化任务插入到薄弱知识点附近

前置条件：

- 薄弱点为 `递归`
- 后续计划中存在相关任务

操作：

- 生成调整后计划

期望结果：

- 新增或调整出递归强化任务
- 任务类型可为 `review`、`practice` 或 `reinforcement`

编写原因：

- F5 不能只移动日期，还要对学习问题做补救。

## 9. 阶段六：调整预览与保存

### TC-F5-026 生成调整预览不覆盖原计划

前置条件：

- 当前 `study_plan` 已存在

操作：

- 点击自动重排或调用生成调整预览

期望结果：

- 原 `study_plan` 保持不变
- 调整结果保存到 `pending_adjusted_plan` 或等价临时状态

编写原因：

- PRD 要求用户确认后才保存。

### TC-F5-027 调整前后差异可计算

前置条件：

- 原计划和调整后计划都存在

操作：

- 生成差异视图

期望结果：

- 能列出被移动日期的任务
- 能列出新增强化任务
- 能列出被压缩或拆分的任务

编写原因：

- 页面需要展示调整前后对比，帮助用户决定是否保存。

### TC-F5-028 用户取消调整时保留原计划

前置条件：

- 已生成调整预览

操作：

- 用户取消或不点击保存

期望结果：

- F3 仍展示原计划
- `pending_adjusted_plan` 可被清除

编写原因：

- 用户必须拥有最终控制权。

### TC-F5-029 用户确认后保存新计划

前置条件：

- 已生成合法调整预览

操作：

- 用户点击保存调整

期望结果：

- 当前 `study_plan` 被替换为调整后计划
- `last_review_report` 被保存
- F3 可以读取新计划

编写原因：

- F5 的最终结果必须回流到 F3。

### TC-F5-030 非法调整结果不能保存

前置条件：

- 调整后计划存在每日超时或超过截止日期

操作：

- 用户点击保存调整

期望结果：

- 保存被拒绝
- 页面显示明确错误
- 原计划保持不变

编写原因：

- 保存前必须再次校验，防止异常结果进入主状态。

## 11. 阶段八：持久化与集成

- 保存复盘报告

- Repository 收到保存请求

前置条件：

期望结果：

## 12. 阶段九：异常与边界

### TC-F5-041 任务列表为空时复盘可控

前置条件：

- `StudyPlan` 存在，但任务列表为空

操作：

- 生成复盘

期望结果：

- 完成率为 0 或返回无任务提示
- 不发生除零错误

编写原因：

- 防止空计划结构导致崩溃。

### TC-F5-042 任务状态非法时校验失败

前置条件：

- 某任务状态为 `unknown`

操作：

- 分析任务进度

期望结果：

- 返回状态非法错误
- 不生成错误复盘

编写原因：

- F3/F5 状态枚举必须一致。

### TC-F5-043 任务缺少 ID 时可生成稳定标识

前置条件：

- 部分任务 `id` 为空

操作：

- 分析任务进度或生成差异

期望结果：

- 系统能生成稳定临时 ID 或返回明确错误
- 差异计算不混淆任务

编写原因：

- F3 早期任务可能没有 ID，F5 需要处理迁移状态。

### TC-F5-044 当前日期晚于截止日期时提示目标已过期

前置条件：

- 当前日期晚于 `goal.deadline`

操作：

- 尝试重排计划

期望结果：

- 系统提示目标已过期
- 不生成假装可执行的新计划

编写原因：

- 过期目标需要用户修改截止日期或重新生成计划。

### TC-F5-045 重排后任务顺序保持知识依赖

前置条件：

- 任务 A 是任务 B 的前置知识

操作：

- 生成调整后计划

期望结果：

- 任务 A 不晚于任务 B

编写原因：

- 动态调整不能破坏学习路径。

## 14. F5 验收通过标准

F5 通过验收需要满足：

- 能从 F3 当前计划读取任务状态
- 能正确计算当前周期完成率
- 能识别延期任务和连续未完成知识点
- 能生成结构化复盘报告
- 能基于剩余时间生成调整后计划
- 调整后计划不超过每日可学习时间
- 调整后计划不超过目标截止日期
- 调整后计划仍能被 F3 展示
- 用户确认前不会覆盖原计划
- 用户确认后能保存调整结果
- LLM 调用服从统一 `USE_REAL_LLM` 开关
- 页面包含完成情况表格、复盘输入框、自动重排按钮、调整预览和保存按钮
