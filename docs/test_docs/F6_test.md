# F6 学习计划导出测试用例方案

## 1. 测试目标

F6 的目标是：用户可以把当前学习计划和复盘报告导出为可保存、可分享、可直接查看的文件。MVP 必须支持 Markdown 和 HTML 导出，PDF 作为后续增强预留接口但不要求真实生成。

本测试方案覆盖：

- Markdown 学习计划导出
- HTML 学习计划导出
- PDF 导出预留行为
- 导出内容完整性
- 导出内容与当前页面计划一致性
- 中文内容编码与显示
- 任务完成状态导出
- 复盘报告导出
- 空计划保护
- 文件命名规则
- Streamlit 下载交互
- 导出异常处理
- 与 F2、F3、F5、F7 的集成边界

## 2. 需求依据

### 2.1 PRD 依据

PRD 中 F6 导出要求包括：

- 支持 Markdown 学习计划导出。
- 支持 HTML 学习计划导出。
- PDF 学习计划作为后续增强。
- 导出内容包括学习计划和复盘报告。
- 技术方案中导出能力为 Markdown / HTML / PDF。
- MVP 完成定义中要求用户可以导出学习计划。

### 2.2 features.md 依据

features.md 对 F6 的要求包括：

- 用户可以导出学习计划和复盘报告，方便保存和分享。
- MVP 必须支持 Markdown、HTML。
- PDF 为后续增强。
- 导出内容包括学习目标、总体路线、阶段计划、周计划、每日任务、学习方法、风险提示、复习安排、时间预算、当前完成状态、复盘报告。
- 需要定义 `Exporter`、`MarkdownExporter`、`HTMLExporter`、`PDFExporter`。
- 导出内容与当前页面计划一致。
- Markdown 结构清晰。
- HTML 可直接打开查看。
- 文件名包含学习主题和日期。
- 没有计划时不能导出，并给出提示。
- 测试要求包含关键字段、中文不乱码、已完成任务状态能导出。

## 3. 功能边界

### 3.1 输入

F6 至少接收：

- 当前 `StudyPlan`
- 可选 `ReviewReport`
- 导出格式：`markdown`、`html`，预留 `pdf`
- 当前日期或导出时间
- 当前任务状态、任务备注、任务日期、任务时长
- 可选文件名生成参数

### 3.2 输出

F6 至少输出：

- Markdown 文本或字节内容
- HTML 文本或字节内容
- 下载文件名
- MIME 类型
- 无计划或不支持格式时的明确错误

### 3.3 不做范围

MVP 阶段不要求：

- 真实 PDF 渲染和排版
- 自动上传到云盘
- 自动邮件分享
- 日历文件 `.ics` 导出
- 多用户权限隔离
- 富文本编辑器导出
- 导出模板在线配置

## 4. 建议领域模型与接口

测试可以驱动实现以下抽象：

```python
Exporter
MarkdownExporter
HTMLExporter
PDFExporter
ExportRequest
ExportResult
```

字段建议：

```text
ExportRequest
  - study_plan
  - review_report
  - format
  - exported_at

ExportResult
  - filename
  - content
  - mime_type
  - extension

Exporter
  - export(request) -> ExportResult
```

格式建议：

```text
Markdown
  extension: .md
  mime_type: text/markdown; charset=utf-8

HTML
  extension: .html
  mime_type: text/html; charset=utf-8

PDF, 预留
  extension: .pdf
  mime_type: application/pdf
```

## 6. 阶段一：导出入口与空状态

### TC-F6-001 无学习计划时不能导出

前置条件：
- 当前 session 或 repository 中没有 `StudyPlan`。

操作：
- 打开导出页面或点击导出按钮。

期望结果：
- 导出按钮不可用，或点击后显示明确提示：“请先生成学习计划”。
- 不生成导出文件。
- 不调用具体 exporter。
- 不出现未捕获异常。

编写原因：
- features.md 明确要求没有计划时不能导出，并给出提示。

### TC-F6-002 有学习计划时显示导出入口

前置条件：
- 当前存在有效 `StudyPlan`。

操作：
- 打开导出页面。

期望结果：
- 页面展示 Markdown 导出入口。
- 页面展示 HTML 导出入口。
- PDF 如出现，应标记为“后续支持”或禁用。
- 用户能清楚区分不同导出格式。

编写原因：
- MVP 必须支持 Markdown 和 HTML，PDF 仅预留。

### TC-F6-003 未选择格式时不能执行导出

前置条件：
- 当前存在有效 `StudyPlan`。
- 页面使用格式选择控件。

操作：
- 不选择格式，直接点击导出。

期望结果：
- 页面提示需要选择导出格式。
- 不生成下载内容。

编写原因：
- 防止格式为空导致 exporter 分发异常。

### TC-F6-004 不支持的导出格式返回明确错误

前置条件：
- 构造 `ExportRequest(format="docx")`。

操作：
- 调用导出用例。

期望结果：
- 返回或抛出明确错误：“不支持的导出格式”。
- 不回退生成错误格式文件。

编写原因：
- 导出格式属于外部输入，必须防御非法值。

### TC-F6-005 PDF 在 MVP 阶段为预留能力

前置条件：
- 当前存在有效 `StudyPlan`。

操作：
- 请求 PDF 导出。

期望结果：
- 若页面展示 PDF：按钮应禁用或提示“PDF 后续支持”。
- 若后端存在 `PDFExporter`：应返回明确的未实现错误。
- 不应生成空 PDF 或伪 PDF。

编写原因：
- PRD 和 features.md 均说明 PDF 是后续增强，MVP 不应制造虚假完成。

## 7. 阶段二：Markdown 导出

### TC-F6-006 Markdown 导出生成 `.md` 文件

前置条件：
- 当前存在有效 `StudyPlan`。

操作：
- 选择 Markdown 导出。

期望结果：
- 返回 `ExportResult.extension == ".md"`。
- 文件名以 `.md` 结尾。
- MIME 类型为 `text/markdown` 或包含 `text/markdown; charset=utf-8`。
- 内容为 UTF-8 文本。

编写原因：
- Markdown 是 MVP 必须支持的格式。

### TC-F6-007 Markdown 包含学习目标信息

前置条件：
- 使用默认测试计划。

操作：
- 导出 Markdown。

期望结果：
- 内容包含学习主题 `Python 编程`。
- 内容包含目标描述。
- 内容包含截止日期 `2026-06-30`。
- 内容包含当前水平。
- 内容包含每日可学习时间和每周学习天数。

编写原因：
- 导出内容必须完整表达学习目标。

### TC-F6-008 Markdown 包含总体路线

前置条件：
- 使用默认测试计划。

操作：
- 导出 Markdown。

期望结果：
- 内容包含“总体路线”标题或等价结构。
- 内容包含 `先学基础语法，再完成练习，最后做小项目`。

编写原因：
- 总体路线是 F2 生成计划的重要输出，F6 必须保留。

### TC-F6-009 Markdown 包含阶段计划

前置条件：
- 计划包含至少一个阶段。

操作：
- 导出 Markdown。

期望结果：
- 内容包含阶段序号。
- 内容包含阶段标题。
- 内容包含阶段目标。
- 内容包含阶段开始日期和结束日期。
- 内容包含里程碑。

编写原因：
- features.md 明确要求导出阶段计划。

### TC-F6-010 Markdown 包含周计划

前置条件：
- 阶段下包含周计划。

操作：
- 导出 Markdown。

期望结果：
- 内容包含周序号。
- 内容包含周计划起止日期。
- 内容包含周目标。
- 内容包含复习重点。

编写原因：
- 学习计划是阶段、周、日三级结构，导出不能丢失周层级。

### TC-F6-011 Markdown 包含每日任务明细

前置条件：
- 周计划下包含多个任务。

操作：
- 导出 Markdown。

期望结果：
- 每个任务至少包含任务标题、日期、时长、类型、状态。
- 若任务有知识点，内容包含知识点列表。
- 若任务有学习方法，内容包含学习方法。
- 若任务有预期产出，内容包含预期产出。

编写原因：
- 用户导出后应能离线执行每日任务。

### TC-F6-012 Markdown 使用清晰结构

前置条件：
- 使用默认测试计划。

操作：
- 导出 Markdown。

期望结果：
- 文档以一级标题开头。
- 学习目标、总体路线、阶段计划、复习安排、风险提示等为清晰分节。
- 阶段和周计划有层级关系。
- 任务列表使用表格或列表表达，阅读顺序稳定。

编写原因：
- features.md 要求 Markdown 格式结构清晰。

### TC-F6-013 Markdown 特殊字符不破坏结构

前置条件：
- 任务标题包含 `#`、`|`、`*`、反引号等 Markdown 特殊字符。

操作：
- 导出 Markdown。

期望结果：
- 特殊字符不会破坏表格列数或标题层级。
- 内容仍能被 Markdown 阅读器正常解析。

编写原因：
- 用户目标和任务内容来自自由文本或 LLM，必须处理 Markdown 特殊字符。

## 8. 阶段三：HTML 导出

### TC-F6-014 HTML 导出生成 `.html` 文件

前置条件：
- 当前存在有效 `StudyPlan`。

操作：
- 选择 HTML 导出。

期望结果：
- 返回 `ExportResult.extension == ".html"`。
- 文件名以 `.html` 结尾。
- MIME 类型为 `text/html` 或包含 `text/html; charset=utf-8`。
- 内容包含完整 HTML 文档结构。

编写原因：
- HTML 是 MVP 必须支持的格式。

### TC-F6-015 HTML 可直接打开查看

前置条件：
- 已生成 HTML 导出内容。

操作：
- 将 HTML 内容保存为文件并用浏览器打开。

期望结果：
- 浏览器可正常渲染。
- 页面标题可读。
- 主要计划内容可见。
- 不依赖本地开发服务器。
- 不依赖外部 CDN 才能显示核心内容。

编写原因：
- features.md 明确要求 HTML 可直接打开查看。

### TC-F6-016 HTML 包含 UTF-8 编码声明

前置条件：
- 使用包含中文的默认测试计划。

操作：
- 导出 HTML。

期望结果：
- HTML 包含 `<meta charset="utf-8">` 或等价声明。
- 中文标题、任务、复盘内容不乱码。

编写原因：
- features.md 明确要求中文内容不乱码。

### TC-F6-017 HTML 包含关键字段

前置条件：
- 使用默认测试计划。

操作：
- 导出 HTML。

期望结果：
- HTML 文本或 DOM 中包含学习目标、总体路线、阶段计划、周计划、每日任务、复习安排、时间预算。
- 关键字段不只存在于脚本变量中，必须能被用户直接看到。

编写原因：
- HTML 导出是给用户查看和分享的，不应只输出机器数据。

### TC-F6-018 HTML 对用户内容做转义

前置条件：
- 学习目标或任务标题包含 `<script>alert(1)</script>`。

操作：
- 导出 HTML 并打开。

期望结果：
- 页面显示原始文本或安全转义后的文本。
- 脚本不执行。
- HTML 结构不被注入内容破坏。

编写原因：
- 学习目标、备注和 LLM 输出都可能包含 HTML 特殊字符，导出必须防注入。

### TC-F6-019 HTML 样式不影响内容可读性

前置条件：
- 使用包含多个阶段和任务的计划。

操作：
- 导出 HTML 并查看。

期望结果：
- 即使没有外部 CSS，内容仍按清晰层级显示。
- 表格或列表不丢列。
- 长任务标题可换行。

编写原因：
- 导出文件应能长期保存，不能依赖脆弱的外部样式资源。

## 10. 阶段五：当前页面一致性

### TC-F6-027 导出内容反映 F3 修改后的任务状态

前置条件：
- 用户在 F3 将 `task-1` 从 `todo` 改为 `done`。
- 当前页面状态已更新。

操作：
- 导出 Markdown 和 HTML。

期望结果：
- 导出文件中 `task-1` 状态为 `done` 或“已完成”。
- 不导出修改前的 `todo` 状态。

编写原因：
- features.md 明确要求导出内容与当前页面计划一致。

### TC-F6-028 导出内容反映 F3 修改后的任务日期

前置条件：
- 用户在 F3 将某任务日期从 `2026-06-04` 改为 `2026-06-06`。

操作：
- 导出 Markdown 和 HTML。

期望结果：
- 导出文件中该任务日期为 `2026-06-06`。
- 不出现旧日期。

编写原因：
- 导出必须读取当前计划，而不是初始生成结果。

### TC-F6-029 导出内容反映 F3 修改后的任务时长

前置条件：
- 用户在 F3 将某任务时长从 60 分钟改为 45 分钟。

操作：
- 导出 Markdown 和 HTML。

期望结果：
- 导出文件中该任务时长为 45 分钟。
- 时间预算若由当前计划重新计算，也应与当前任务一致。

编写原因：
- F3 支持编辑任务时长，F6 必须导出编辑后的版本。

### TC-F6-030 导出内容反映 F5 保存后的调整计划

前置条件：
- F5 已生成调整预览。
- 用户点击保存调整。
- 当前 `StudyPlan` 已替换为调整后计划。

操作：
- 导出 Markdown 和 HTML。

期望结果：
- 导出的是调整后的计划。
- 包含新增强化任务。
- 已移动任务显示新日期。

## 21. 完成定义

F6 测试完成需要满足：

- Markdown 导出测试通过。
- HTML 导出测试通过。
- 无计划导出保护测试通过。
- 中文编码测试通过。
- 当前任务状态导出测试通过。
- 文件名规则测试通过。
- 导出内容与当前计划一致性测试通过。
- PDF 预留行为清晰，不误导用户。
- 导出操作不改变学习计划、任务状态或复盘报告。
