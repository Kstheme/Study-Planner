# F3 学习计划展示与编辑测试用例

## 1. 测试目标

F3 的目标是让用户可以在 Streamlit 中查看学习计划、编辑任务，并标记完成状态。

根据 `docs/PRD.md` 和 `docs/features.md`，F3 必须覆盖：

- 展示总体目标摘要
- 展示总体学习路线
- 展示阶段计划
- 展示周计划
- 展示今日任务
- 展示本周任务
- 展示风险提示
- 展示复习安排
- 展示学习方法
- 展示学习进度图表
- 编辑任务状态
- 编辑任务日期
- 编辑任务时长
- 编辑任务备注
- 校验非法任务修改
- 将更新后的计划交给 F5 复盘与动态调整

## 2. 测试范围

### 2.1 包含范围

- Streamlit 学习计划看板页面
- `StudyPlan` 展示逻辑
- 阶段、周、日三级结构展示
- 任务编辑逻辑
- 任务状态更新逻辑
- 学习进度计算逻辑
- 页面状态保存逻辑

### 2.2 不包含范围

- F2 学习计划生成
- F4 资料上传与问答
- F5 复盘重排
- F6 导出
- PostgreSQL 持久化，F3 第一版可以先使用 Session State

## 3. 前置条件

测试 F3 前需要准备一份有效 `StudyPlan`，至少包含：

- `goal`
- `overall_route`
- `phases`
- 每个 phase 至少一个 `weekly_plan`
- 每个 weekly_plan 至少一个 `task`
- `methods`
- `time_budget`
- `risks`
- `review_schedule`

任务状态至少支持：

- `todo`
- `doing`
- `done`
- `skipped`

## 4. 阶段划分

F3 测试分 6 个阶段：

| 阶段 | 目标 |
|---|---|
| 阶段 1 | 空状态与页面基础 |
| 阶段 2 | 学习计划完整展示 |
| 阶段 3 | 任务编辑 |
| 阶段 4 | 编辑校验 |
| 阶段 5 | 进度统计与图表 |
| 阶段 6 | 状态保存与后续流程衔接 |

## 5. 阶段 1：空状态与页面基础

### F3-1-01 无学习计划时显示空状态提示

测试流程：

1. 清空 Session State 中的 `study_plan`。
2. 打开学习计划看板页。
3. 查看页面内容。

预期结果：

- 页面不报错。
- 页面提示用户还没有学习计划。
- 页面提示用户先去学习目标配置页生成计划。

编写原因：

- 用户可能直接进入看板页，系统必须优雅处理空状态。

### F3-1-02 无学习计划时不显示编辑控件

测试流程：

1. 清空 `study_plan`。
2. 打开学习计划看板页。
3. 检查页面是否存在任务编辑控件。

预期结果：

- 不显示任务状态编辑。
- 不显示任务日期编辑。
- 不显示任务时长编辑。
- 不显示保存按钮。

编写原因：

- 没有计划时编辑控件没有意义，避免用户误操作。

### F3-1-03 学习计划看板页可以正常加载

测试流程：

1. 打开学习计划看板页。
2. 不执行任何操作。

预期结果：

- 页面可以正常渲染。
- 没有 Python 异常。
- 没有 Streamlit 状态 key 缺失错误。

编写原因：

- 先保证页面基础稳定，再测试复杂展示。

## 6. 阶段 2：学习计划完整展示

### F3-2-01 展示总体目标摘要

测试流程：

1. 在 Session State 中放入有效 `StudyPlan`。
2. 打开学习计划看板页。
3. 查看目标摘要区域。

预期结果：

- 显示学习主题。
- 显示学习目标。
- 显示截止日期。
- 显示当前水平。
- 显示每日学习时间。
- 显示每周学习天数。

编写原因：

- 用户需要确认当前看板对应的是哪个学习目标。

### F3-2-02 展示总体学习路线

测试流程：

1. 准备包含 `overall_route` 的 `StudyPlan`。
2. 打开看板页。

预期结果：

- 页面显示总体学习路线。
- 内容与 `plan.overall_route` 一致。

编写原因：

- PRD 要求展示总体学习路线。

### F3-2-03 展示阶段计划 Tabs

测试流程：

1. 准备包含多个 `StudyPhase` 的计划。
2. 打开看板页。
3. 查看阶段区域。

预期结果：

- 每个阶段都有对应 Tab 或清晰分区。
- 显示阶段标题。
- 显示阶段目标。
- 显示阶段起止日期。
- 显示阶段里程碑。

编写原因：

- F2 生成阶段结构，F3 必须能按阶段展示。

### F3-2-04 展示周计划

测试流程：

1. 在某个阶段下准备多个 `WeeklyPlan`。
2. 打开对应阶段。

预期结果：

- 显示每周编号。
- 显示周目标。
- 显示周起止日期。
- 显示复习重点。

编写原因：

- PRD 要求展示本周任务和阶段计划，周计划是中间层。

### F3-2-05 展示每日任务

测试流程：

1. 准备每周包含多个 `StudyTask` 的计划。
2. 打开周计划。

预期结果：

- 显示任务标题。
- 显示任务日期。
- 显示任务时长。
- 显示任务类型。
- 显示关联知识点。
- 显示学习方法。
- 显示预期产出。
- 显示任务状态。

编写原因：

- 每日任务是用户实际执行计划的最小单位。

### F3-2-06 展示今日任务

测试流程：

1. 准备包含今天日期任务的计划。
2. 打开看板页。

预期结果：

- 今日任务区域显示今天的任务。
- 不显示其他日期任务。

编写原因：

- 今日任务是用户进入看板后最重要的信息。

### F3-2-07 今日无任务时显示提示

测试流程：

1. 准备不包含今天任务的计划。
2. 打开看板页。

预期结果：

- 今日任务区域提示今天没有学习任务。
- 页面不报错。

编写原因：

- 不是每天都有任务，空今日任务需要正常处理。

### F3-2-08 展示本周任务表格

测试流程：

1. 准备包含当前自然周任务的计划。
2. 打开看板页。

预期结果：

- 本周任务表格显示当前周任务。
- 包含日期、标题、时长、状态、预期产出。

编写原因：

- PRD 明确要求展示本周任务表格。

### F3-2-09 展示风险提示

测试流程：

1. 准备包含 `risks` 的计划。
2. 打开看板页。

预期结果：

- 页面显示所有风险提示。

编写原因：

- 用户需要看到计划执行风险。

### F3-2-10 展示复习安排

测试流程：

1. 准备包含 `review_schedule` 的计划。
2. 打开看板页。

预期结果：

- 显示每日复习分钟数。
- 显示每周复习日。
- 显示复习策略。

编写原因：

- PRD 要求展示复习安排。

### F3-2-11 展示学习方法

测试流程：

1. 准备包含 `methods` 的计划。
2. 打开看板页。

预期结果：

- 页面显示学习方法列表。

编写原因：

- 用户需要知道用什么方式执行计划。

## 7. 阶段 3：任务编辑

### F3-3-01 标记任务为完成

测试流程：

1. 准备一个状态为 `todo` 的任务。
2. 在页面将任务状态改为 `done`。
3. 点击保存或触发更新。

预期结果：

- 任务状态变为 `done`。
- 页面刷新后状态仍为 `done`。

编写原因：

- 标记完成是 F3 的核心编辑能力。

### F3-3-02 标记任务为进行中

测试流程：

1. 准备一个状态为 `todo` 的任务。
2. 将状态改为 `doing`。

预期结果：

- 任务状态变为 `doing`。

编写原因：

- 用户可能需要标记当前正在学习的任务。

### F3-3-03 标记任务为跳过

测试流程：

1. 准备一个任务。
2. 将状态改为 `skipped`。

预期结果：

- 任务状态变为 `skipped`。

编写原因：

- 跳过任务会影响 F5 复盘，需要被记录。

### F3-3-04 修改任务日期

测试流程：

1. 准备一个任务。
2. 将任务日期改为目标截止日期前的某一天。
3. 保存。

预期结果：

- 任务日期更新成功。
- 任务仍出现在对应日期的任务列表中。

编写原因：

- 用户需要调整学习安排。

### F3-3-05 修改任务时长

测试流程：

1. 准备一个任务。
2. 将任务时长从 60 分钟改为 45 分钟。
3. 保存。

预期结果：

- 任务时长更新为 45 分钟。
- 当日总时长重新计算。

编写原因：

- 用户需要根据实际情况调整任务负载。

### F3-3-06 修改任务备注

测试流程：

1. 准备一个任务。
2. 输入备注，例如“今天先看前两节”。
3. 保存。

预期结果：

- 任务备注保存成功。
- 页面能展示备注。

编写原因：

- 备注可以帮助用户记录执行细节。

### F3-3-07 批量修改多个任务状态

测试流程：

1. 准备多个 `todo` 任务。
2. 将其中两个改为 `done`。
3. 保存。

预期结果：

- 被修改任务状态正确更新。
- 未修改任务保持原状态。

编写原因：

- 用户可能一次性更新一天或一周的完成情况。

## 8. 阶段 4：编辑校验

### F3-4-01 拒绝非法任务状态

测试流程：

1. 尝试将任务状态设置为 `invalid_status`。

预期结果：

- 系统拒绝更新。
- 显示状态非法提示。

编写原因：

- F5 依赖任务状态枚举，不能出现未知状态。

### F3-4-02 拒绝超过截止日期的任务日期

测试流程：

1. 将任务日期改为 `goal.deadline` 之后。
2. 保存。

预期结果：

- 更新失败。
- 显示任务日期不能超过截止日期。

编写原因：

- 计划必须在用户截止日期内完成。

### F3-4-03 拒绝早于今天的任务日期

测试流程：

1. 将任务日期改为今天之前。
2. 保存。

预期结果：

- 更新失败。
- 显示任务日期不能早于今天。

编写原因：

- 不应把未来计划编辑成过去任务。

### F3-4-04 拒绝非正数任务时长

测试流程：

1. 将任务时长改为 0 或负数。
2. 保存。

预期结果：

- 更新失败。
- 显示任务时长必须大于 0。

编写原因：

- 任务必须有实际学习时间。

### F3-4-05 拒绝当日总时长超过每日可学习时间

测试流程：

1. 准备某天已有多个任务。
2. 修改其中一个任务时长，使当天总时长超过 `goal.daily_available_minutes`。
3. 保存。

预期结果：

- 更新失败。
- 显示当日任务总时长超过每日可学习时间。

编写原因：

- 防止用户编辑后破坏计划可执行性。

### F3-4-06 拒绝空任务标题

测试流程：

1. 如果页面支持编辑标题，将任务标题清空。
2. 保存。

预期结果：

- 更新失败。
- 显示任务标题不能为空。

编写原因：

- 空标题任务不可执行。

### F3-4-07 长备注可保存但不破坏页面

测试流程：

1. 在备注中输入较长文本。
2. 保存。
3. 查看任务卡片或表格。

预期结果：

- 备注保存成功。
- 页面布局不明显错乱。

编写原因：

- 用户可能记录较详细的学习情况。

## 9. 阶段 5：进度统计与图表

### F3-5-01 计算总任务数

测试流程：

1. 准备包含多个阶段、周、任务的计划。
2. 打开看板页。

预期结果：

- 总任务数等于所有 weekly_plan.tasks 数量之和。

编写原因：

- 总任务数是完成率计算基础。

### F3-5-02 计算已完成任务数

测试流程：

1. 准备 5 个任务，其中 2 个状态为 `done`。
2. 打开看板页。

预期结果：

- 已完成任务数为 2。

编写原因：

- 用户需要看到完成进度。

### F3-5-03 计算完成率

测试流程：

1. 准备 4 个任务，其中 1 个完成。
2. 打开看板页。

预期结果：

- 完成率为 25%。

编写原因：

- 完成率是学习进度最重要指标之一。

### F3-5-04 没有任务时完成率为 0

测试流程：

1. 准备一个没有任务的计划或空任务集合。
2. 打开看板页。

预期结果：

- 完成率显示为 0。
- 不出现除零错误。

编写原因：

- 防止边界情况导致页面崩溃。

### F3-5-05 统计每日计划分钟数

测试流程：

1. 准备多天任务，每天不同时长。
2. 打开看板页。

预期结果：

- 每日计划分钟数统计正确。

编写原因：

- 图表需要展示每日学习负载。

### F3-5-06 统计每周计划分钟数

测试流程：

1. 准备多个周计划。
2. 打开看板页。

预期结果：

- 每周计划分钟数统计正确。

编写原因：

- 用户需要看到不同周的学习负载。

### F3-5-07 状态更新后完成率实时变化

测试流程：

1. 准备 2 个任务，均为 `todo`。
2. 将其中一个标记为 `done`。
3. 查看完成率。

预期结果：

- 完成率从 0% 变为 50%。

编写原因：

- 编辑操作必须反映到进度统计。

### F3-5-08 图表可以正常渲染

测试流程：

1. 准备完整计划。
2. 打开看板页。

预期结果：

- 进度图表正常显示。
- 没有图表渲染异常。

编写原因：

- PRD 要求图表能直观反映学习进度。

## 10. 阶段 6：状态保存与后续流程衔接

### F3-6-01 编辑后更新 Session State 中的 StudyPlan

测试流程：

1. 准备 `study_plan`。
2. 修改一个任务状态。
3. 保存。
4. 检查 Session State 中的 `study_plan`。

预期结果：

- Session State 中的计划已更新。

编写原因：

- F5 需要读取最新计划做复盘。

### F3-6-02 页面刷新后保留当前编辑结果

测试流程：

1. 修改任务状态。
2. 刷新页面或重新进入看板页。

预期结果：

- 如果使用 Session State，当前会话内编辑结果保留。
- 如果接入 PostgreSQL，刷新后仍能恢复编辑结果。

编写原因：

- 用户不应因为页面刷新丢失刚刚编辑的进度。

### F3-6-03 更新后的计划可被 F5 读取

测试流程：

1. 在 F3 中将某些任务标记为 `done`、`skipped`。
2. 进入 F5 复盘调整页。

预期结果：

- F5 能读取最新任务状态。
- F5 看到的完成情况与 F3 一致。

编写原因：

- F3 是 F5 复盘数据来源。

### F3-6-04 更新后的计划可被 F6 导出

测试流程：

1. 在 F3 修改任务状态和备注。
2. 进入 F6 导出。

预期结果：

- 导出内容包含最新任务状态。
- 导出内容包含最新备注。

编写原因：

- 导出必须反映当前计划，而不是旧计划。

## 12. 手动验收流程

### 主流程验收

1. 通过 F1 填写学习目标。
2. 通过 F2 生成学习计划。
3. 进入学习计划看板。
4. 查看总体目标、总体路线、阶段计划、周计划、今日任务、本周任务。
5. 将一个任务标记为完成。
6. 修改另一个任务的日期和时长。
7. 查看完成率是否变化。
8. 尝试把任务日期改到截止日期之后，确认被拒绝。
9. 进入 F5 页面，确认能看到最新任务状态。

### 通过标准

- 页面能完整展示阶段、周、日三级计划。
- 用户可以修改任务状态、日期、时长、备注。
- 非法修改会被拒绝。
- 进度统计正确。
- 编辑结果能传递给后续复盘和导出流程。

## 13. F3 完成定义

F3 完成时必须满足：

- 用户能在页面上看懂学习计划。
- 用户能查看总体路线、阶段、周、日任务。
- 用户能编辑任务状态、日期、时长、备注。
- 用户不能保存明显非法的任务修改。
- 页面能显示学习进度。
- 更新后的计划能被 F5 和 F6 使用。
